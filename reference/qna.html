0003 경계를 넘는 데이터

new 타입(인자) { … }에서 { }는 뭔가요?

객체 초기화자(object initializer)예요. 객체를 만든 직후에 프로퍼티 값을 넣는 문법이에요. 두 부분은 하는 일이 달라요.

부분하는 일순서
(인자)생성자를 호출해요1번째
{ 이름 = 값, … }만들어진 객체의 프로퍼티에 값을 대입해요2번째
 
C# · 직접 실행한 결과 (.NET 10.0.203)var a = new Box("생성자 인자") { Name = "초기화자" };
//  출력: 생성자("생성자 인자") 실행
//  a.Name = 초기화자          ← 생성자가 넣은 값을 { }가 덮어씀 (생성자 → { } 순서)

var b = new Box { Name = "괄호 생략" };
//  출력: 생성자() 실행          ← 인자 없는 생성자를 쓸 땐 ( )를 생략할 수 있어요

var c = new Box { Tags = { "x", "y" } };
//  c.Tags = 기본,x,y           ← 목록을 바꾸지 않고 기존 목록에 Add

위 결과에서 알 수 있는 것:

  • 순서: 생성자가 먼저 실행되고, 그다음 { } 안의 대입이 일어나요.
  • ( ) 생략: 인자 없는 생성자를 쓸 때는 괄호를 생략할 수 있어요. 0002의 new SleepRecord { ChildId = … }가 이 경우예요.
  • init과의 관계: init 프로퍼티는 "객체를 만들 때만" 값을 넣을 수 있다고 했죠. { }가 바로 그 "만들 때"예요. 그래서 init과 required는 객체 초기화자와 짝으로 쓰여요.
  • Tags = { … }처럼 = 뒤가 다시 중괄호이면 컬렉션 초기화자예요. 새 목록으로 바꾸는 게 아니라 기존 목록에 Add해요. 그래서 Converters = { new JsonStringEnumConverter() }는 옵션이 이미 가진 변환기 목록에 하나를 추가하는 거예요.
아래 두 코드는 같은 일을 해요var options = new JsonSerializerOptions(JsonSerializerDefaults.Web)
{
    WriteIndented = true,
    Converters = { new JsonStringEnumConverter() },
};

// ↕ 같음

var options = new JsonSerializerOptions(JsonSerializerDefaults.Web);
options.WriteIndented = true;
options.Converters.Add(new JsonStringEnumConverter());

TS로 비유하면 Object.assign(new Box(), { name: "…" })와 비슷해요. 다만 C#은 컴파일러가 프로퍼티 이름과 타입을 검사하고, required를 빠뜨리면 컴파일 오류를 내 줘요.

차이는 누가 JsonSerializer를 호출하느냐예요.

그러면 enum을 문자열로 바꾸는 것처럼 설정을 바꾸고 싶을 때는 어떻게 할까요? 프레임워크가 가진 옵션 객체를 받아서 덧붙여요. 앱이 시작할 때 Program.cs에서 한 번만 해요.

Program.csbuilder.Services.AddControllers()
    .AddJsonOptions(o =>
        o.JsonSerializerOptions.Converters.Add(new JsonStringEnumConverter()));
  • o => …는 람다예요. 프레임워크가 설정 묶음 o를 넘겨주면, 우리는 그 안의 o.JsonSerializerOptions(프레임워크가 만든 옵션 객체)를 고쳐요.
  • 여기에는 new JsonSerializerOptions가 없어요. 그게 "직접 만들지 않고 덧붙인다"는 뜻이에요.
  • 프레임워크가 쓰는 옵션은 웹 기본값과 같아요. Microsoft 문서는 JsonSerializerOptions.Web을 "ASP.NET Core가 웹 앱에 쓰는 기본 옵션"이라고 설명해요. 그래서 따로 설정하지 않아도 이름은 camelCase로 나가고, enum은 숫자로 나가요.

실제로 실행해 본 결과(.NET 10.0.203, 위 Controller에 POST /diapers):

보낸 content설정 없음AddJsonOptions로 변환기 추가

설정이 없으면 TS가 보낸 "Poo"를 받지 못하고, 응답으로도 숫자를 내보내요. 0001에서 배운 400(클라이언트 잘못) 응답을 프레임워크가 자동으로 만들어 준다는 것도 볼 수 있어요. 이건 나중에 오류 처리 수업에서 다뤄요.

콘솔 앱의 "옵션은 한 번 만들어 재사용"과 API의 "Program.cs에서 한 번 설정"은 같은 원칙이에요. 규칙은 앱 전체에 한 곳에 둔다는 거예요. Controller 수업에서 직접 만들어 볼 거예요.

0002 C# 첫걸음

record class와 record struct로 나뉘는데, 엔티티를 class로 하라는 게 앞뒤가 맞나요?

타입 종류(참조 타입인지 값 타입인지)와 동등성 기준(무엇이 같으면 같은지)은 서로 다른 축이에요.

타입 종류기본 동등성
class참조참조 (같은 객체인가)
record / record class참조값 (같은 값인가)
struct값값 (==는 직접 정의해야 함)
record struct값값 (== 자동 생성)

EF Core가 문제 삼는 것은 동등성이에요. 자세한 내용은 아래 질문에 있어요.

record도 참조 타입인데, 엔티티로 쓰면 안 되는 이유는?

컴파일은 돼요. 하지만 두 세계의 규칙이 부딪혀요.

  • EF Core: 키 하나에 인스턴스 하나만 두고 참조 동등성으로 추적해요. 그 인스턴스를 직접 수정해서 저장해요. 그래서 엔티티의 Equals를 재정의하지 말라고 권해요.
  • record: Equals와 ==를 값 기준으로 강제로 재정의하고, with로 복사본을 만드는 방식을 권해요.
var a = await db.SleepRecords.SingleAsync(r => r.Id == id); // EF가 a를 추적 중
var b = a with { EndedAt = now };
db.Update(b);  // InvalidOperationException: ... another instance with the key value ... is already being tracked.

요청과 응답 데이터에는 정체성(id 추적)이 없어요. 그래서 값 동등성과 불변성이 자연스럽고, record가 잘 맞아요.

nullable의 유용한 점은? ?.는 왜 빠졌나요?

0002 수업에서 빠뜨린 부분이에요. 선언 쪽(?)만 다루고 사용하는 쪽을 빼먹었어요.

  • a?.B: a가 null이면 결과도 null이고, 뒤에 이어지는 호출은 실행되지 않아요.
  • a ?? b: a가 null이면 b를 써요.
  • x ??= y: x가 null일 때만 y를 넣어요.
var minutes = sleep.EndedAt?.Subtract(sleep.StartedAt).TotalMinutes;  // 진행 중이면 null
var label = minutes?.ToString("0") ?? "진행 중";

진짜 가치는 컴파일러가 null 상태를 추적한다는 데 있어요. ?를 붙인 변수를 검사 없이 쓰면 경고가 나요. 반대로 ?가 없으면 null이 아니라고 믿고 써도 돼요. 그래서 null 검사를 꼭 필요한 곳에만 하게 돼요.

DateTimeOffset을 로컬 시간대로 보여 줄 수 있나요?

  • ToLocalTime(): 코드가 실행되는 컴퓨터의 시간대로 바꿔요. 서버에서 부르면 서버의 시간대가 돼요.
  • TimeZoneInfo.ConvertTime(dto, 시간대): 원하는 시간대를 직접 지정해서 바꿔요.

실무 팁: 서버는 오프셋을 포함한 시각을 그대로 보내고, 보여 줄 때 브라우저에서 변환하세요. 사용자의 시간대는 브라우저가 가장 잘 알아요. (0003 수업의 "화면에 보여 줄 때" 참고)

TS에서는 enum을 권장하지 않는데, C# enum과 JSON은 어떻게 연결하나요?

TS에서는 문자열 유니온(as const 배열에서 뽑아낸 타입)을 써요. C#에서는 기본적으로 enum이 숫자로 나가니, JsonStringEnumConverter를 앱 전체에 한 번 등록해서 이름으로 내보내요. 이런 정보를 찾는 방법은 경계 질문이에요. 0003 수업 전체가 이 질문에 대한 답이에요.
