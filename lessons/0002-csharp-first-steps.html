C# 첫걸음: 수면 기록 모델을 C#으로 만들기

이번 수업의 목표: baby-log의 수면 기록을 C# 클래스로 직접 쓰고, 프로퍼티 하나하나에 init과 set, required, ? 중 무엇을 붙일지 이유를 대며 고를 수 있게 되는 것.

태블릿 OK 읽기와 퀴즈 약 20분 · PC 실습 약 20분

이미 아는 것은 그대로 가져와요

Microsoft의 "JavaScript·TypeScript 개발자를 위한 C# 안내"에 따르면 세 언어는 비슷한 점이 많아요.[1]

  • 중괄호와 세미콜론을 쓰는 비슷한 문법. => 화살표 함수(C#에서는 람다 식이라고 불러요)도 있어요.
  • 같은 async / await 키워드. TS의 Promise<string> 자리에 C#은 Task<string>을 써요.
  • 가비지 컬렉터. npm 자리에는 NuGet이 있어요.

달라지는 핵심은 하나예요. C#은 강타입 언어라서 "모든 변수에 타입이 있고 그 타입은 바뀌지 않아요".[1] TS의 타입은 컴파일 후 사라지지만, C#의 타입은 실행 중에도 남아 있어요. 객체지향 경험이 있으니 클래스나 상속 개념은 건너뛰고, C#만의 문법에 집중할게요.

같은 모델, 두 언어

baby-log의 수면 기록을 TS로 쓴다면 아마 왼쪽처럼 쓸 거예요. 오른쪽이 C# 버전이에요.

TypeScripttype DiaperContent = "Pee" | "Poo" | "Both";

interface SleepRecord {
  readonly id: string;
  readonly childId: string;
  readonly authorId: string;
  startedAt: Date;
  endedAt: Date | null;
}

const isOngoing = (r: SleepRecord) =>
  r.endedAt === null;
C#public enum DiaperContent { Pee, Poo, Both }

public class SleepRecord
{
    public Guid Id { get; init; } = Guid.NewGuid();
    public required Guid ChildId { get; init; }
    public required Guid AuthorId { get; init; }
    public required DateTimeOffset StartedAt { get; set; }
    public DateTimeOffset? EndedAt { get; set; }

    public bool IsOngoing => EndedAt is null;
}

한 줄씩 짚어 볼게요.

① 프로퍼티와 { get; set; } / { get; init; }

C#에서는 필드를 그대로 공개하지 않고 프로퍼티(property)로 노출해요. get은 읽기, set은 언제든 쓰기를 뜻해요. init은 "객체를 만들 때만 값을 넣을 수 있고, 그 뒤로는 바꿀 수 없음"을 뜻해요.[4] TS의 readonly와 비슷한 역할이에요.

② required: 빠뜨리면 컴파일이 안 돼요

required를 붙인 프로퍼티는 객체를 만들 때 반드시 값을 넣어야 해요. 빠뜨리면 컴파일 오류가 나요.[3] 반대로 init만 붙이면 값을 안 넣어도 컴파일은 돼요. Microsoft 문서도 "init은 호출하는 쪽에 값 설정을 강제하지 않는다"고 말해요.[4] 그래서 "만들 때 꼭 넣어야 하고, 나중에는 못 바꾸는 값"에는 required와 init을 함께 써요.

③ DateTimeOffset?: 물음표는 "없을 수 있음"

타입 뒤의 ?는 "null일 수 있다"는 뜻이에요. 진행 중인 수면에는 아직 종료 시각이 없으니 EndedAt은 DateTimeOffset?이에요. 새 .NET 프로젝트는 기본으로 이 검사(<Nullable>enable</Nullable>)가 켜져 있어요. 다만 string 같은 참조 타입에서 ?는 컴파일러에게 의도를 알려 줄 뿐이고, 실행 동작은 바꾸지 않아요.[5] TS의 strictNullChecks와 거의 같은 역할이에요.

④ 왜 DateTime이 아니라 DateTimeOffset?

Microsoft는 "앱 개발에서는 DateTimeOffset을 기본 날짜·시간 타입으로 고려하라"고 권해요.[6] DateTimeOffset은 UTC와의 시차를 함께 저장해요. 그래서 서버가 다른 시간대에 있어도, 해외에 사는 할머니가 기록을 봐도 "몇 시 몇 분"이 꼬이지 않아요.

⑤ enum: TS 문자열 유니온의 C# 버전

정해진 몇 가지 값 중 하나만 고르는 타입은 enum으로 만들어요.[7] 다만 함정이 하나 있어요. enum 멤버는 기본적으로 0부터 번호가 매겨지고, 값을 넣지 않은 enum 변수의 기본값은 0이에요.[7] 위 코드에서는 첫 멤버 Pee가 0이라서, 값을 빠뜨리면 아무 오류 없이 "소변"으로 저장돼요. 그래서 enum 프로퍼티에도 required를 붙여요.

⑥ IsOngoing => EndedAt is null

=>로 정의한 읽기 전용 프로퍼티예요. 값을 따로 저장하지 않고 읽을 때마다 계산해요. is null은 C#의 패턴 매칭(pattern matching) 문법이에요.[1] "진행 중인 수면"이라는 도메인 용어가 코드에 그대로 드러나는 게 좋은 점이에요.

class와 record: 언제 무엇을?

C#에는 데이터를 담는 데 특화된 record가 있어요. 한 줄로 정의할 수 있고, 값이 같으면 같은 객체로 취급해요.[2]

C# · recordpublic record StartSleepRequest(Guid ChildId, DateTimeOffset StartedAt);

var a = new StartSleepRequest(childId, now);
var b = new StartSleepRequest(childId, now);
Console.WriteLine(a == b);              // True: 값이 같으면 같다

var c = a with { StartedAt = now.AddMinutes(-10) };  // 일부만 바꾼 복사본

그럼 SleepRecord는 왜 record가 아닐까요? Microsoft 문서에 이유가 나와 있어요. Entity Framework Core는 참조 동등성(reference equality)에 의존하기 때문에, record는 "EF Core의 엔티티 타입으로 적합하지 않아요".[2] 그래서 baby-log에서는 이렇게 나눠요.

용도타입예
DB에 저장되는 엔티티classSleepRecord, ChildAccess
주고받는 데이터 (요청, 응답 등)recordStartSleepRequest

바뀌면 안 되는 것은 컴파일러가 막게 하세요. ChildId, AuthorId는 init이에요. 기록이 다른 아이에게 옮겨 가거나 작성자가 바뀌는 일은 도메인에 없기 때문이에요. 반면 StartedAt, EndedAt은 set이에요. 할머니가 시간을 잘못 눌렀을 때 고칠 수 있어야 하니까요(우리가 정한 기록 수정 규칙). 도메인 규칙을 타입에 새겨 두면 6개월 뒤의 나나 동료가 실수로 규칙을 깨려 할 때 코드 리뷰가 아니라 컴파일러가 먼저 막아 줘요. 유지보수성은 이렇게 얻어요.

오버엔지니어링 경계: 기록이 네 종류니까 처음부터 abstract class Record 같은 공통 부모를 만들고 싶어질 거예요. 아직은 참으세요. 공통점이 "있을 것 같다"가 아니라 실제 코드에서 같은 중복이 반복될 때 묶어도 늦지 않아요. 잘못 만든 상속 구조는 중복보다 고치기 어려워요. 이건 공식 규칙이 아니라 실무 경험칙이에요.

TS에서 서버 날짜는 Date가 아니라 string으로 받으세요. JSON에는 날짜 타입이 없어요. 값은 문자열, 숫자, 객체, 배열, true/false, null뿐이에요.[8] 그래서 C#의 DateTimeOffset은 "2026-11-03T21:30:00+09:00" 같은 문자열로 도착해요. TS 타입에 startedAt: Date라고 적으면 타입은 Date인데 실제 값은 string인 거짓말하는 타입이 돼요. 이런 타입은 런타임에 .getTime is not a function 같은 오류를 내요. API 응답 타입에는 startedAt: string이라고 정직하게 적고, 화면에 보여 줄 때 변환하세요.

마찬가지로 C#의 EndedAt이 null이면 JSON에도 null로 와요. 그래서 TS에서는 "없을 수도 있는 키"를 뜻하는 endedAt?: string보다 endedAt: string | null이 서버와의 계약을 더 정확하게 표현해요.

떠올리기 연습

위를 보지 말고 C# 코드를 머릿속으로 써 본 다음 펼쳐 보세요.

TS의 readonly childId: string(만들 때 꼭 넣고 이후 변경 불가)을 C#으로?public required Guid ChildId { get; init; }. 꼭 넣어야 하니 required, 이후 변경 불가이니 init이에요.
진행 중일 수 있는 수면의 "종료 시각" 프로퍼티는?public DateTimeOffset? EndedAt { get; set; }. 없을 수 있으니 ?, 나중에 채우고 고칠 수 있으니 set이에요.
성장 기록 요청(아이 id, 측정 시각, 키 cm)을 record 한 줄로?public record RecordGrowthRequest(Guid ChildId, DateTimeOffset MeasuredAt, decimal HeightCm);. 이름은 달라도 괜찮아요. 엔티티가 아니라 주고받는 데이터라서 record라는 점이 핵심이에요. (키 같은 측정값에 decimal과 double 중 무엇을 쓸지는 DB 수업에서 다뤄요.)

퀴즈

수면이 진행 중이면 종료 시각이 아직 없어요. EndedAt에 가장 알맞은 타입은?

"없을 수 있음"은 ?로 표현하고, 날짜·시간의 기본 타입으로는 Microsoft가 DateTimeOffset을 권장해요.[6]

ChildId는 만들 때 반드시 넣어야 하고, 그 뒤로는 바꿀 수 없어야 해요. 알맞은 선언은?

init만 붙이면 "만들 때만 설정 가능"이지만, 값을 넣으라고 강제하지는 않아요.[4] 강제하려면 required를 함께 붙여요.[3]

같은 값으로 만든 record 인스턴스 두 개를 ==로 비교하면?

record는 "같은 타입이고 같은 값을 담고 있으면 같다"는 값 동등성을 가져요.[2] 일반 class라면 서로 다른 인스턴스이므로 false예요.

DB에 저장할 SleepRecord를 record가 아닌 class로 만드는 이유는?

Microsoft 문서에 따르면 EF Core는 참조 동등성에 의존하기 때문에, record는 EF Core 엔티티 타입으로 적합하지 않아요.[2]

string?의 ?는 실행 중에 무엇을 바꾸나요?

참조 타입의 nullable 표시는 "완전히 컴파일 타임 기능"이에요. string과 string?은 실행 중에는 같은 System.String이에요.[5] 컴파일러가 경고로 실수를 잡아 줄 뿐이에요.

TS의 type DiaperContent = "Pee" | "Poo" | "Both"를 C#으로 옮길 때 가장 흔한 방법은?

정해진 이름 있는 값 중 하나를 고르는 타입은 enum이에요.[7] 기본값이 0(첫 멤버)이라는 함정이 있으니, enum 프로퍼티에는 required를 붙이는 걸 잊지 마세요.

기록 종류가 넷(수유, 수면, 기저귀, 성장)이에요. 첫 버전에서 가장 알맞은 설계 판단은?

추상화는 실제 중복을 보고 나서 해도 늦지 않아요. 잘못 만든 공통 부모는 중복보다 고치기 어려워요. 모든 기록을 클래스 하나로 합치면 "모유 수유인데 기저귀 내용물 칸이 있는" 이상한 상태가 생겨요.

  2. 새 콘솔 프로젝트를 만들어요. 
    dotnet new console -n CSharpFirstSteps
cd CSharpFirstSteps
  3. Program.cs의 내용을 아래 코드로 바꿔요. 맨 위에 실행 코드를 두고 타입 선언은 그 아래에 두는 순서를 지켜야 해요. 
    var childId = Guid.NewGuid();
var now = DateTimeOffset.Now;

var sleep = new SleepRecord
{
    ChildId = childId,
    AuthorId = Guid.NewGuid(),
    StartedAt = now,
};
Console.WriteLine($"진행 중? {sleep.IsOngoing}");

sleep.EndedAt = now.AddHours(1);
Console.WriteLine($"진행 중? {sleep.IsOngoing}");

var a = new StartSleepRequest(childId, now);
var b = new StartSleepRequest(childId, now);
Console.WriteLine($"a == b ? {a == b}");

public class SleepRecord
{
    public Guid Id { get; init; } = Guid.NewGuid();
    public required Guid ChildId { get; init; }
    public required Guid AuthorId { get; init; }
    public required DateTimeOffset StartedAt { get; set; }
    public DateTimeOffset? EndedAt { get; set; }

    public bool IsOngoing => EndedAt is null;
}

public record StartSleepRequest(Guid ChildId, DateTimeOffset StartedAt);
